So we now disqualify each based on our needs:
1.Set--it will be used for some functions
A Set cannot have duplicate values, so what happens the first names of two customers match?
counter: We can use the full names instead of the first name. Full names can't match, but what if somehow they just do? It is possible
A set has its use
For example: We can Use a set to avoid duplicate number plate entries or ID_Number
we can also use sets to store use data, create new sets for each user(no names will overlap)

2.Dictionary--will work
Well for starters we have multiple entries,and therefore dictionaries are not the most efficient. But for parking lot data it is the best.
WHY? Because a parking lot space can be either vacant or occupied and can have one index only
example :{"A1":"OCCUPIED} #Parking space A1 is occupied

When billing users, we can map a single user to a list of payments,
example : {"Abdul":300}#Much more still left out, research is required
3.Tuple--least best
We cannot modify tuples, so we cannot add users to an already made tuple

4.List--seems to work best
Because it can be modified once created. So our list will hold sets or dictionaries to our user data.
